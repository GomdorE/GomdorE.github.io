여러 작업을 동시에 시작하면 실제 처리 속도보다 작업 전환 비용이 커질 수 있습니다. 가장 단순한 대응 방법은 현재 처리 중인 일에 필요한 창만 남기는 것입니다.

## 적용 방법

**1) 현재 작업에 필요한 창만 남깁니다.** 브라우저 탭도 포함합니다. 나중에 확인할 페이지는 북마크나 작업 메모로 옮긴 뒤 닫습니다.

**2) 알림 확인 시간을 정합니다.** 메신저와 메일을 계속 열어두는 대신 업무 특성에 맞는 확인 시간을 정합니다. 즉시 대응이 필요한 연락망은 별도로 구분해야 합니다.

**3) 떠오른 일은 실행하지 말고 기록합니다.** 현재 작업과 관계없는 일이 생각나면 한 줄만 적고 원래 작업으로 돌아갑니다.

```
할 일: 3개
지금 열린 창: 1개
```

## 적용할 때 생기는 변화

**초기에는 확인 욕구가 커질 수 있습니다.** 알림과 탭을 닫으면 무언가 놓치는 느낌이 들 수 있으므로, 확인 시간을 캘린더에 명시하는 편이 좋습니다.

**개별 작업 속도보다 완료율이 달라집니다.** 한 번에 하나를 마친 뒤 다음으로 이동하면 시작만 해둔 작업이 쌓이는 문제를 줄일 수 있습니다.

**회의가 많은 날에는 효과가 제한적입니다.** 짧은 간격으로 일정이 끊기는 날에는 집중 작업보다 회신, 정리, 검토처럼 중단 가능한 업무를 배치하는 편이 적합합니다.

## 적합한 경우

- 탭이 20개씩 열려 있는 분
- 하루가 끝나면 뭘 했는지 잘 기억 안 나는 분
- 집중이 끊기는 원인을 작업 환경에서 먼저 찾고 싶은 분

반대로 짧은 요청을 계속 받아 처리해야 하는 업무에는 그대로 적용하기 어렵습니다. 이 경우에는 요청을 모으는 창구와 우선순위 규칙을 먼저 설계해야 합니다.

핵심은 항상 창 하나만 사용하는 것이 아니라, **현재 동시에 진행 중인 작업의 수를 의식적으로 제한하는 것**입니다.
